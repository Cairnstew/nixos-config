# Deploy Workflow

> Skill for deploying NixOS configurations via nixos-anywhere, Ventoy USB, and related tools

## Overview

Deployments use per-host wrapper packages (`nix run .#deploy-<host>`, generated by
`modules/flake-parts/nixos-anywhere-deploy/`) that invoke `nixos-anywhere` with the
right disko mode and optional host-key provisioning. Multi-boot USB management uses
`ventoy-deploy`. Common operations are available via `just` recipes.

## Quick Reference

```bash
# Activate local configuration
just local

# Activate a remote host (SSH into an existing, already-running system)
just activate <hostname>

# Deploy to a new machine via nixos-anywhere (auto-detects disko mode)
just deploy-run <hostname> <ssh-target>
#   e.g. just deploy-run desktop nixos@nixos
#        just deploy-run server 192.168.1.100
#   Equivalent: nix run .#deploy-<hostname> -- <ssh-target>

# Deploy desktop with existing partitions (dual-boot useExisting — disko nodev: mounts/formats only, does NOT partition)
just deploy-desktop [ssh-target]

# Generate a host SSH key for first-boot secret decryption (host-key provisioning)
nix run .#prepare-keys-<hostname>
#   writes .deploy-keys/<hostname>/extra-files/etc/ssh/ssh_host_ed25519_key(.pub)
#   then add the pubkey to agenix-manager and run: agenix-manager rekey
```

## Deployment Architecture

```
┌─────────────────────────────────────────────────────────┐
│              nix run .#deploy-<host> -- <target>         │
│   (per-host wrapper from modules/flake-parts/            │
│    nixos-anywhere-deploy/config.nix)                    │
│  ┌───────────────────────────────────────────────────┐   │
│  │  nixos-anywhere                                  │   │
│  │  1. kexec into NixOS live environment             │   │
│  │  2. partition disk (disko) when host has a       │   │
│  │     disk-config.nix sidecar with real disks       │   │
│  │  3. install NixOS to target                       │   │
│  │  4. reboot                                        │   │
│  └───────────────────────────────────────────────────┘   │
│  - identity: $HOME/.ssh/id_ed25519 (or agentIdentity)    │
│  - --extra-files from .deploy-keys/<host>/extra-files     │
│    when that directory exists                            │
└─────────────────────────────────────────────────────────┘
```

## Host Types

### Standard Hosts (laptop, server, wsl, minimal)
Use `just deploy-run <host> <target>` (equivalent to `nix run .#deploy-<host> -- <target>`).
The wrapper auto-detects disko mode from the host's `disk-config.nix` sidecar.

### Desktop (dual-boot with Windows)
- Uses `useExisting` disko mode — does NOT partition the disk
- The NixOS partition must exist before deployment
- Use: `just deploy-desktop [target]`
- One-time setup from live ISO:
  ```bash
  sudo sgdisk -n 0:0:0 -t 0:8300 -c 0:nixos /dev/sda
  sudo mkfs.ext4 -L nixos /dev/sda4
  ```

## Ventoy Multi-Boot USB

### Build and Deploy
```bash
# Build the deploy ISO (requires --impure for agenix)
sudo just ventoy-iso

# Deploy ISOs + config to Ventoy USB (auto-detect device)
sudo just ventoy-deploy

# Specify device explicitly
sudo just ventoy-deploy /dev/sdb

# Install Ventoy to device (destructive!)
sudo just ventoy-deploy --install /dev/sdb

# Build bundle without deploying
just ventoy-bundle
```

### Verify Deployment
```bash
# Check deploy state
cat /run/media/*/VENTOY/ventoy/.deploy-state

# Verify ISO integrity
sha256sum <store-iso> <usb-iso>

# List deployed ISOs
ls -lah /run/media/*/VENTOY/iso/linux/
```

## Secret Injection Deployment

Some hosts need secrets decrypted on first boot. When a host has a `disk-config.nix`
sidecar (or uses dualBoot), the deploy wrapper expects a pre-generated host key so that
agenix secrets encrypted to that key are decryptable immediately after install.

1. **Prepare** (`nix run .#prepare-keys-<host>`): generates
   `.deploy-keys/<host>/extra-files/etc/ssh/ssh_host_ed25519_key(.pub)`.
   Refuses to overwrite an existing keydir unless `--force` is passed.
2. **Register**: add the generated public key to the agenix-manager key config in
   `modules/nixos/common.nix` (under `agenixManager.keys.groups.systems`).
3. **Rekey**: `agenix-manager rekey` to re-encrypt secrets for the new host.
4. **Deploy**: `just deploy-run <host> <target>` — the wrapper picks up
   `.deploy-keys/<host>/extra-files` and passes it as `--extra-files`. If the keydir is
   missing when the wrapper expects it, it prints a warning telling you to run
   `nix run .#prepare-keys-<host>`.

**If secrets fail on first boot:**
- The host SSH key was freshly generated and doesn't match encryption
- Fix: add the new host key to `agenixManager.keys.groups.systems`, run
  `agenix-manager rekey`, rebuild
- Or regenerate the key dir with `nix run .#prepare-keys-<host> -- --force` and redeploy

## Testing Deployments

```bash
# VM-test a host config (validates the system closure; no target machine needed)
just vm-test <hostname>
#   runs: nix build .#<hostname>-vm
#   NOTE: a -vm package currently exists only for desktop (desktop-vm,
#   desktop-vm-headless). For other hosts there is no .#<hostname>-vm output yet.

# Build the desktop smoke-test suite (systemd smoke tests + health checks)
just test

# Run all nixtest suites (unit, snapshot, script tests)
just nixtest
```

## Troubleshooting

### "nixos-anywhere not found"
Deploy wrapper references `inputs.nixos-anywhere` — only available on Linux systems.
Run from the flake root on a Linux host.

### "disko devices not defined"
Desktop uses `useExisting` mode — partition must exist before deployment.
Create partition manually (see above) and use `just deploy-desktop`.

### Ventoy ISO corruption
The deploy script verifies SHA-256 after copy. If verification fails:
1. Delete partial ISO: `rm /run/media/*/VENTOY/iso/linux/nixos-installer*.iso`
2. Re-deploy: `sudo just ventoy-deploy`
3. Verify manually: `sha256sum <store-iso> <usb-iso>`

### Post-deploy: machine unreachable
- Check Tailscale status: the deploy target may not have connected to tailnet yet
- Use direct IP if available (Ethernet/WiFi on same LAN)
- Or physically access the machine to check `tailscale status`
